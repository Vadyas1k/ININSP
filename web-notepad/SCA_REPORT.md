# 📦 SCA Report (Software Composition Analysis)

##  Инструменты
- **SBOM Generator** (`scripts/gen_sbom.py`) → экспорт `pip list` в CycloneDX 1.4
- **pip-audit** → поиск CVE в зависимостях
- **Docker** → изоляция окружения от глобальных пакетов

## 📄 SBOM
Файл: `sbom.json` (CycloneDX 1.4)  
Содержит **~230 пакетов** (глобальное окружение Windows).  
Для проекта `web-notepad` релевантны только прямые зависимости:

| Пакет | Версия | Роль в проекте |
|-------|--------|----------------|
| Flask | 3.0.0 | Веб-фреймворк |
| Werkzeug | 3.1.8 | WSGI / HTTP утилиты |
| Jinja2 | 3.1.6 | Шаблонизатор |
| MarkupSafe | 3.0.3 | Экранирование |
| requests | 2.32.5 | HTTP-клиент (если используется) |
| sqlite3 | built-in | Хранение заметок |

## 🔍 Анализ уязвимостей

### ✅ Прямые зависимости (безопасны)
- `Flask`, `Werkzeug`, `Jinja2`, `MarkupSafe` используют актуальные патчи.
- `requests==2.32.5` закрывает известные CVE (Cookie leak, Proxy auth).

### ⚠️ Критичные находки в глобальном окружении
| Пакет | Версия | Проблема | Влияние на проект |
|-------|--------|----------|-------------------|
| `setuptools` | 63.2.0 | CVE-2022-40897, CVE-2024-6345 (ReDoS, path traversal) |  Не влияет (не в `requirements.txt`) |
| `urllib3` | 1.26.20 | CVE-2023-43804, CVE-2023-45803 (Cookie/Proxy leak) | ❌ Не влияет (транзитивная dev-зависимость) |
| `pip` | 25.3 | PYSEC-2026-196, CVE-2026-1703 | ❌ Только для сборки/обновлений |

### 📊 Вывод
Большинство уязвимостей относятся к **глобальным инструментам разработки** (`aider-chat`, `litellm`, `PySide6`, `matplotlib`), которые не входят в `requirements.txt` и не используются в рантайме блокнота. Риск для продакшена отсутствует благодаря изоляции.

## 🛠 Способы устранения и минимизации рисков

1. **Изоляция окружения**  
   ✅ Проект запускается в Docker (`python:3.10-slim`) → глобальные уязвимые пакеты не попадают в контейнер.

2. **Фиксация версий**  
   ✅ В `requirements.txt` указаны точные версии (`==`), что предотвращает drift и установку уязвимых транзитивных зависимостей.

### 3. Автоматическая проверка в CI
Настроен прямой запуск `pip-audit` в GitHub Actions:
- При каждом push/PR сканируется `requirements.txt`
- Найденные CVE логируются в отчёт билда
- Пайплайн возвращает ошибку при обнаружении HIGH/CRITICAL уязвимостей → блокирует merge до обновления зависимостей
